# LLM Wiki — Schema & Operating Rules

這是你（LLM）維護這個知識庫的完整說明文件。每次操作前必須先讀這份文件。

---

## 知識庫結構

```
Knowledge/
├── CLAUDE.md          ← 本文件：規則與工作流程（你的行動指南）
├── Index.md           ← 所有 Wiki 頁面的目錄（你必須維護）
├── Log.md             ← 操作記錄，只能追加（你必須維護）
├── Sources/           ← 原始資料（只讀，絕對不修改）
├── Wiki/
│   ├── Concepts/      ← 概念頁面（原理、方法、框架）
│   ├── Entities/      ← 實體頁面（人物、工具、模型、組織）
│   └── Summaries/     ← 摘要頁面（每份來源的濃縮筆記）
└── Templates/         ← 頁面模板（建立新頁面時使用）
```

---

## 三種核心操作

### 1. Ingest（消化新來源）

當使用者提供新文件、文章、論文、網頁時執行：

**步驟：**
1. 讀取 `Sources/` 中的原始資料（或使用者貼上的內容）
2. 在 `Wiki/Summaries/` 建立摘要頁面
3. 更新或建立相關的 `Wiki/Concepts/` 和 `Wiki/Entities/` 頁面
4. 若有矛盾，在受影響頁面加上 `> ⚠️ 矛盾：...` 的 blockquote 標記
5. 更新 `Index.md`
6. 在 `Log.md` 追加一筆記錄

**格式：**
```
## [YYYY-MM-DD] Ingest: <來源標題>
- 新增頁面：...
- 更新頁面：...
- 矛盾標記：...
```

---

### 2. Query（查詢知識庫）

當使用者提問時執行：

**步驟：**
1. 讀取 `Index.md` 找出相關頁面
2. 讀取相關 Wiki 頁面
3. 綜合多頁面內容，給出有來源引用的回答
4. 若這次查詢產生有價值的新洞見，可選擇建立 `Wiki/Concepts/` 新頁面
5. 在 `Log.md` 追加記錄

**格式：**
```
## [YYYY-MM-DD] Query: <問題摘要>
- 參考頁面：...
- 新建頁面：（如有）
```

---

### 3. Lint（健康檢查）

當使用者要求「整理」「檢查」「維護」時執行：

**檢查項目：**
- `Index.md` 是否與實際檔案一致
- 是否有孤兒頁面（沒有任何其他頁面連結到它）
- 是否有死連結（`[[頁面名]]` 指向不存在的頁面）
- 是否有 `⚠️ 矛盾` 標記尚未解決
- 是否有空的或內容過少的頁面
- 在 `Log.md` 追加 Lint 記錄

## 頁面規範

### Frontmatter（每個 Wiki 頁面都必須有）

```yaml
---
title: 頁面標題
type: concept | entity | summary
tags: [標籤1, 標籤2]
sources: [來源檔名或URL]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 連結規範

- 使用 `[[頁面名]]` 連結 Wiki 內部頁面
- 使用 `[文字](URL)` 連結外部資源
- 每個頁面至少要有 2 個對外連結（連到其他 Wiki 頁面）

### 檔名規範

- Concepts：`Wiki/Concepts/概念名稱.md`（中文或英文皆可，保持一致）
- Entities：`Wiki/Entities/實體名稱.md`
- Summaries：`Wiki/Summaries/YYYY-MM-DD_來源標題.md`

---

## 重要原則

1. **Sources 是聖域**：`Sources/` 資料夾內的檔案永遠不能被修改或刪除
2. **Log 只追加**：`Log.md` 只能在最後加新記錄，不能編輯舊記錄
3. **Index 即時更新**：每次 Ingest 後必須立刻更新 `Index.md`
4. **標記矛盾，不要自行裁定**：發現矛盾時標記讓使用者決定，不要自行刪除舊資訊
5. **原子化知識**：一個 Concepts 頁面只講一件事，寧願多建幾個小頁面

---

## 如何新增來源

使用者可以：
- 把檔案直接放進 `Sources/` 資料夾，然後說「幫我消化 Sources/ 裡的新檔案」
- 直接貼上文字內容，說「幫我把這個加進知識庫」
- 提供 URL，說「幫我把這篇文章加進知識庫」
